# Fixing issues

If the user reports an issue that needs fixing, review what you know and develop hypotheses about possible causes of the problem.

For each hypothesis, if you cannot rule it out, establish how it can be tested and a plan for fixing the issue if it proves true.

Present the hypotheses in order of likelihood, and explain the various tests to the user. Where possible, run these tests yourself to establish which is correct.

If there are multiple approaches to the fix, present them to the user, and recommend the fix that's "least hacky", simplest, and introduces the least technical debt / fewest special cases into the code base.
